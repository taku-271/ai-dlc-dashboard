# Intent Statement: AI-DLC 並列 Intent ダッシュボード（v2: 判断の下書き）

> 入力元: 元の依頼文（画面仕様3・4、確認範囲の記録）、v1 の成果（`261011-dashboard-v1` の要件定義と実装）、`intent-capture-questions.md` の回答

## 課題（Problem Statement）

v1 で「どの Intent が人の判断を待っているか」は一目で分かるようになった。しかし、承認待ちの Intent を見つけた後に「前回から何が変わったか」を確かめ、承認や修正依頼の言葉を組み立てる作業は、まだ Claude Code の会話とファイルを行き来して手で行っている。また、どこまで確認して承認したか（差分だけか、全文か）が記録に残らない。

## 対象利用者（Target Customer）

- 当面: 依頼者本人（v1 と同じ）
- 将来: チームメンバー（承認の確認範囲が記録に残ることで、後から判断の根拠を辿れる）

## 成功指標（Success Metrics）

| 指標 | 合格基準 |
|------|----------|
| 変更の確認 | 承認待ちの Intent について、前回の承認以降の成果物の変化を、ダッシュボードだけで機械的な差分（git diff）として確かめられる |
| 文面の作成 | 判断（承認／修正依頼）を選ぶと Claude Code に貼る文面ができ、ワンクリックでコピーできる |
| 確認範囲の記録 | 文面を作るたびに、確認範囲（差分のみ／全文）と判断内容が `aidlc/` の外に記録される。文面にも確認範囲が1行入る |
| 読み取り専用の維持 | v1 と同じく、`aidlc/` と `.claude/` に書き込まない。AI-DLC の状態は変えない |

## きっかけ（Initiative Trigger）

v1 の完成（2026-10-11）。元の依頼文で v2 として予定していた範囲。

## スコープの方針（Initial Scope Signal）

- `poc` スコープ。質問1の回答により**最小版**に絞る
- 対象: 承認待ちの差分表示、全文への導線、判断と確認範囲の選択、文面の生成とコピー、確認範囲の記録
- 対象外（次の Intent 以降）: AI の仮定・上流から辿れない追加・抜け候補の3区分レビュー（書き方の取り決めが先に必要）、理由付き承認のフェーズ制限と「不一致あり」表示、ブロック時の詳細画面

## 制約

- `aidlc/` と `.claude/` は読み取り専用。承認・差し戻しは Claude Code の会話内で行い、ダッシュボードは文面を作るだけ
- 差分は git diff などの機械的な差分を正とする。AI による要約は使わない
- 外部サービスへの送信なし。ローカルで完結
- v1 の技術スタック（Bun + TypeScript、依存なし）を引き継ぐ

## 仮定（Assumptions）

- 仮定1: 「前回の承認」の時点は、git の履歴から機械的に決められる（例: 直前の `GATE_APPROVED` を含むコミット）。成り立つかは要件定義で調べる
- 仮定2: v1 の実機確認（依頼者が帰宅後に実施）で大きな問題が出た場合は、v2 の要件定義で優先して扱う
