# 要件定義: AI-DLC 並列 Intent ダッシュボード（v2: 判断の下書き）

> 上流: `ideation/intent-capture/intent-statement.md`（承認済み）、`inception/requirements-analysis/requirements-analysis-questions.md`（回答済み）
> v1 の要件（`261011-dashboard-v1/inception/requirements-analysis/requirements.md`）と実装（`dashboard/`）を前提にし、ここでは v2 で追加・変更する点だけを書く。
> scope-document、team-practices、business-overview、architecture、code-structure は、poc スコープ（greenfield）ではステージ自体を実行しないため存在しない。

## 意図の分析

承認待ちの Intent について、ダッシュボードの中で次のことをできるようにする。

- 前回の承認以降に何が変わったかを、機械的な差分（git diff）で確かめる
- 承認か修正依頼かを決め、Claude Code に貼る文面を作ってコピーする
- どこまで確認したか（差分のみ／全文）を、毎回記録に残す

成功指標（intent-statement）は「ダッシュボードだけで変化を確かめて文面を作れること」と「確認範囲が毎回記録に残ること」の両方。

## 調査結果

### 「前回の承認」の時点を git から特定できるか

取得可（条件付き）。

- audit には、承認のたびに `GATE_APPROVED` イベントとその `**Timestamp**` 行が残る。
- その行を最初に含んだコミットは `git log -S "<Timestamp 行>" -- <audit ファイル>` で特定できる。v1 の Intent で試し、requirements-analysis の承認（`2026-10-11T05:07:27Z`）を含むコミット `a958357` を特定できた。
- **注意 1**: 承認したのと同じコミットに、次のステージの成果物が入ることがある（v1 の `a958357` には次のステージの計画書も入っていた）。そのコミットを差分の起点にすると、その成果物が差分から漏れる。そのため、起点は「承認を含むコミットの1つ前」とする。前のステージの最後の修正が差分に混ざることはあるが、見落としは起きない。
- **注意 2**: 直近の承認がまだコミットされていないことは、実際によく起きる（調査時点でも v2 の intent-capture の承認は作業ツリーにしかなかった）。その場合は、コミット済みの1つ前の承認まで遡って起点にする。範囲が広がる側に倒すので、見落としは起きない。
- **注意 3**: `-S` は、同じ秒の Timestamp 行を持つ複数のイベントに反応して、複数のコミットを返すことがある。最も古いコミットを使う。

### 外部コマンドと書き込みについて v1 から変える点

- v1 は「書き込み API も外部コマンドも一切使わない」ことをテストで確かめていた（NFR-001）。
- v2 は記録の保存（書き込み）と git の呼び出しが必要なので、このルールを「決めた場所への書き込み」と「決めたコマンドだけ」に絞り直す（NFR-101、NFR-102）。`aidlc/` と `.claude/` に書き込まないこと、AI-DLC の CLI を呼ばないことは変えない。

## 機能要件

### 承認待ちの詳細画面

- FR-101: 一覧画面の人待ちリストとカードから、承認待ちの Intent の詳細画面を開ける。
- FR-102: 詳細画面には、Intent 名、現在のステージ、フェーズ、待ち時間、Claude Code で戻る先（FR-113）を表示する。

### 差分

- FR-103（差分の起点）: 既定の起点は「その Intent の直近の `GATE_APPROVED` を含むコミット（`git log -S` が返すうち最も古いもの）の1つ前」とする。
  - 直近の承認がまだコミットされていない場合は、コミット済みの承認まで遡って同じ方法で起点を決め、「直近の承認（<ステージ名>）が未コミットのため、<遡ったステージ名> の承認時点から表示しています」と注意文を出す。
  - コミット済みの承認が1つもない場合は、「Intent の記録ディレクトリを最初に追加したコミット（最も古いもの）の1つ前」とする。
  - 「1つ前」のコミットがない（リポジトリ最初のコミットだった）場合は、空の状態と比べる（すべて追加として出す）。
  - どれも特定できない場合は、起点を「取得不可」とし、理由を表示する。
- FR-104（起点の切り替え）: その Intent に、自分（FR-122 の確認者）が以前に作った記録がある場合（FR-120）、起点を「前回ダッシュボードで確認した時点」（その記録に残した HEAD のコミット。FR-121）に切り替えられる。他人の記録は起点に使わない。記録のコミットは NFR-102 の検証を通ったものだけ使う。
- FR-105（差分の対象）:
  - 全フェーズ: Intent の記録ディレクトリ。ただし `audit/` と各 `memory.md` は除く
  - Construction フェーズでは、これに加えてリポジトリ内の `aidlc/`、`.claude/`、`.aidlc-dashboard/` 以外のファイル（アプリのコード）。並行して動いている別の Intent のコード変更も混ざりうる（既知の制約として画面に注記する）
- FR-106（作業ツリーを含める）: 差分は、起点のコミットと現在の作業ツリーを比べる（まだコミットしていない変更も含める）。git の管理下にない新しいファイルは「新規」として一覧に出す。
- FR-107（表示）: 変更されたファイルの一覧（追加／変更／削除、行数）と、ファイルごとの unified diff を表示する。差分は git の出力をそのまま使い、AI による要約は出さない。バイナリファイルは「バイナリ（差分は表示しない）」とだけ出す。1ファイルの差分が 2,000 行を超える場合は先頭だけを表示し、省略したことと全文への導線を出す。
- FR-108（全文への導線）: 一覧の各ファイルから、そのファイルの全文（作業ツリーの現在の内容）を開ける。開けるのは、その時点の差分の一覧に載っているファイルと、Intent の記録ディレクトリ内のファイルだけ。シンボリックリンクを解決した実際のパス（realpath）がリポジトリの外になるもの、`.git/` 配下のものは拒否する。作業ツリーで削除されたファイルは「削除済み」と表示し、全文は開かない。

### 判断と文面

- FR-110（入力）: 判断（「承認」か「修正依頼」）と確認範囲（「差分のみ」か「全文」）を選ぶ。「修正依頼」ではコメントの入力を必須にする。必須項目が欠けているときは、文面を作らずに、欠けている項目を表示する。
- FR-111（承認の文面）: Claude Code に貼る文面を日本語で作る。含めるのは、承認であること、Intent 名、ステージ名、確認範囲の1行（例:「確認範囲: 差分のみ（a1b2c3d..作業ツリー、12ファイル）」）。
- FR-112（修正依頼の文面）: 修正依頼であること、Intent 名、ステージ名、確認範囲の1行、入力したコメントを含める。
- FR-113（戻り先）: 文面と一緒に、どこに貼ればよいかを表示する。例:「Intent `261011-dashboard-v2` の Claude Code セッションに貼る。別の Intent がアクティブなら、先に `/aidlc intent dashboard-v2` を実行する」。
- FR-114（コピー）: ボタン1回で文面をクリップボードにコピーする。クリップボードが使えない場合は、文面を選択した状態のテキスト欄を表示する。

### 確認範囲の記録

- FR-120（保存）: 文面を作るたびに、記録を1件保存する。保存先は、読む対象のリポジトリ内の `.aidlc-dashboard/reviews/<Intent の dirName>/<UTC 日時（ミリ秒まで）>-<確認者>.json`。既存のファイルは上書きしない。同じ名前のファイルがすでにある場合は、末尾に連番を付ける。
- FR-121（記録の中身）: Intent、ステージ、判断、確認範囲、差分の起点と終点（コミット、または「作業ツリー」）、記録した時点の HEAD のコミット（終点が作業ツリーでも必ず残す）、差分に含まれたファイルの一覧、コメント、生成した文面、作成日時、確認者。
- FR-122（確認者）: 確認者は `git config user.name` から読む。取れない場合は `unknown` とする。ファイル名に使えない文字は置き換える。
- FR-123（履歴）: 詳細画面に、その Intent でこれまでに作った記録を新しい順に表示する。
- FR-124（共有の運用）: ダッシュボードは記録を書き込むだけで、commit も push もしない。`.aidlc-dashboard/` は、AI-DLC の記録と同じタイミングで Claude Code（または人）が commit する。この運用を `dashboard/README.md` に書く。

## 非機能要件

- NFR-101（書き込みの範囲）: ダッシュボードが書き込むのは `<root>/.aidlc-dashboard/` の中だけ。書き込みは `src/store/` に集め、realpath がこのディレクトリの外になる場合（シンボリックリンク経由を含む）は拒否する。v1 の「`aidlc/` と `.claude/` が変わらない」テストは維持し、v2 の機能（記録の保存を含む）を動かした後でも成り立つことを確かめる。v1 の静的検査（書き込み API と外部コマンドの使用禁止）は、`src/store/`（書き込み）と `src/git/`（外部コマンド）だけを例外にし、それ以外のファイルで使われていたら失敗するように更新する。
- NFR-102（git の呼び出し）: 呼び出してよいのは `git log`、`git diff`、`git show`、`git ls-files`、`git rev-parse`、`git config --get` だけ。質問3で承認された `log`／`diff`／`show` に加え、新しいファイルの一覧（`ls-files`）、コミットの検証（`rev-parse --verify`）、確認者名の取得（`config --get user.name`）のために3つを足した。どれも読み取りだけのコマンド。
  - シェルを通さずに引数を配列で渡し、`GIT_OPTIONAL_LOCKS=0` を付け、10秒で打ち切る。
  - 呼び出しは `src/git/` に集め、許可していないサブコマンドは拒否する。
  - コミットを表す値は、40桁の16進数であることを確かめたうえで `git rev-parse --verify <値>^{commit}` で検証し、通らなければ使わない。パスなどの引数の前には `--` を付け、オプションとして解釈されないようにする。
  - `git diff` と `git show` には常に `--no-ext-diff --no-textconv` を付ける。
  - AI-DLC の CLI は引き続き呼ばない。
- NFR-103（変更系 API の保護）: 記録を保存する API は POST だけを受け付ける。v1 の Host ヘッダーの検査に加えて、`Origin` がダッシュボード自身であることと、独自ヘッダー（例: `X-Dashboard-Request: 1`）があることを確かめる。`Origin` がない場合は拒否する。
- NFR-104（性能）: 100ファイル・1万行規模の差分で、詳細画面が3秒以内に表示される。
- NFR-105（テスト）: 起点の決め方、差分の対象の絞り込み、文面の生成、記録の保存（パスの検査を含む）、git 呼び出しの制限に自動テストを付ける。未コミットの承認を遡ったときの注意文もテストする。git を使うテストは、一時ディレクトリに作ったテスト用のリポジトリで行う。NFR-104 の性能は自動テストではなく、ビルドとテストのステージで1回計測して記録する。
- v1 の非機能要件（ローカル完結、`127.0.0.1` だけで待ち受け、外部依存なし、取得不可の表示）はそのまま引き継ぐ。

## 制約

- 承認・差し戻しは、これまでどおり Claude Code の会話内で行う。ダッシュボードは文面を作るだけで、AI-DLC の状態を変えない。
- 技術スタックは v1 と同じ（Bun + TypeScript、画面は素の HTML/CSS/JS、外部依存なし）。

## 仮定

- 仮定1: 差分を見る対象のリポジトリは、ダッシュボードを起動したリポジトリ（`--root`）と同じ。

## 範囲外

- AI の仮定・上流から辿れない追加・抜け候補の3区分レビュー（書き方の取り決めが先に必要）
- 理由付き承認と、それを許可するフェーズの設定、「不一致あり」の表示
- ブロック時の詳細画面
- ダッシュボードからの直接の承認、commit、push

## 実装計画

コード生成ステージで、次の順に作る。

1. `dashboard/src/git/`: 許可したサブコマンドだけを呼ぶ git 呼び出しモジュールと、そのテスト
2. `dashboard/src/review/baseline.ts`: 差分の起点の決定（FR-103、FR-104）
3. `dashboard/src/review/diff.ts`: 差分の対象の絞り込みと差分の取得（FR-105〜FR-107）
4. `dashboard/src/review/draft.ts`: 入力の検査と文面の生成（FR-110〜FR-113）
5. `dashboard/src/store/`: 記録の保存と読み込み（FR-120〜FR-123）。書き込みはこのモジュールだけ
6. `dashboard/src/server.ts`: 詳細、差分、全文、記録の API を追加
7. `dashboard/public/`: 詳細画面（差分、全文表示、判断フォーム、文面のコピー、履歴）
8. テスト: テスト用の git リポジトリを作る補助と、結合テスト。v1 の読み取り専用テストを NFR-101／NFR-102 に合わせて更新する
9. `dashboard/README.md`: `.aidlc-dashboard/` の commit の運用（FR-124）を追記する
