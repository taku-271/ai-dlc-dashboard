| 候補ユニット | 含む機能 | 依存先 |
|-------------|---------|--------|
| PU-1 読み取り | M-1、M-2、M-13（検出部分） | なし（AI-DLC のファイル形式に依存） |
| PU-2 合図 | M-9（合図を送る側）、M-14（合図を送る側）、M-16（手順書） | なし（Claude Code のフックの仕組みに依存） |
| PU-3 サーバー | M-6、M-7（送る側）、M-9（受ける側）、M-10、M-15（受ける側） | PU-1、PU-2 |
| PU-4 画面 | M-3、M-4、M-5、M-7（受ける側）、M-8、M-11、M-13・M-14（表示）、M-15（ボタン）、M-16（経過時間） | PU-3 |
| 共通 | M-12（自動テスト） | 各ユニット |

依存の流れ（テキスト図）:

```
[PU-1 Read] ---+
               +--> [PU-3 Server] --> [PU-4 Screen]
[PU-2 Signal] -+
```

テキストでの説明: 読み取り（PU-1）と合図（PU-2）は互いに独立しており、並行して作れます。サーバー（PU-3）は両方を使い、画面（PU-4）はサーバーから情報を受け取ります。

## 7. ウォーキングスケルトンの候補（delivery-planning への提案）

各候補ユニットから最小限を取り出し、端から端まで1本通します。

| 候補ユニット | スケルトンに含める最小限 |
|-------------|----------------------|
| PU-1 | 設定ファイルの1プロジェクトから、状態ファイルの `[?]` を読む（M-1・M-2・M-3 の最小部分） |
| PU-2 | フックが合図を1種類送る（M-9 の最小部分） |
| PU-3 | 127.0.0.1 で待ち受け、合図を受けて読み直し、画面へ送る（M-6・M-7・M-9） |
| PU-4 | 承認待ちを1つの一覧に出し、タブタイトルに件数を出す（M-3・M-8 の最小部分） |

最大の不確実性である「ユーザー全体の設定でのフックの動作」（RAID の AS-4）を、最初の段階で確かめられます。
