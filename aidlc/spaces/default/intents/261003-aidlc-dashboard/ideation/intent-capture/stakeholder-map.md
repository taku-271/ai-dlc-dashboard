# Stakeholder Map — AI-DLC 部長ダッシュボード

> ステージ: intent-capture（Ideation）／ スコープ: mvp
> 作成: 2026-10-03（UTC）
> 前提: 開発者は1人で、利用者の範囲は「自分用が主、将来OSSとして公開する可能性あり」（質問票 Q6: B）。
> 関係者の数は少ないものの、「データを書き出す側」と「形式を決める側」がダッシュボードの外にいる点が、このプロジェクトの特徴です。

---

## 1. 関係者と関心事

| ID | 関係者 | 立場 | 主な関心事 | このプロジェクトへの影響 |
|----|--------|------|-----------|-------------------------|
| S-1 | 開発者本人（プロジェクトオーナー） | 利用者／意思決定者／唯一の承認者 | 承認待ちを見落とさないこと。巡回の手間をなくすこと。タブを開いておくだけで気づけること | 要件・優先順位・各承認ゲートの判断をすべて行う |
| S-2 | AI-DLC のAIエージェント群（各 Intent を進める Claude Code セッション） | データを生み出す側（間接的な関係者） | 承認ゲートで開発者の判断を早く得ること（承認待ちの滞留はエージェントの作業停止を意味する） | 状態ファイル・監査ログを書き出す。ダッシュボードはそれを読むだけで、エージェント側には何も求めない |
| S-3 | AI-DLC フレームワーク（aidlc-workflows v2）の作り手 | 外部の影響者 | フレームワーク自身の進化 | 状態ファイルや監査ログの**形式を決める**側。形式が変わるとダッシュボードの読み取りが壊れる可能性がある（intent-statement の R-6） |
| S-4 | 将来の OSS 利用者（AI-DLC を使う他の開発者） | 将来の利用者（影響者） | 導入のしやすさ、設定の分かりやすさ、自分の環境で動くこと | 設定ファイルの分かりやすさ、ドキュメント、フレームワークの複数バージョンへの対応度合いの判断材料になる |

## 2. 意思決定者と影響者

| 区分 | 関係者 | 決めること・与える影響 |
|------|--------|----------------------|
| 意思決定者 | S-1 開発者本人 | すべての承認ゲート、スコープの変更、MVP に含める範囲、OSS 公開の判断 |
| 影響者（強） | S-3 フレームワークの作り手 | 読み取るデータの形式。ダッシュボード側からは変えられない制約 |
| 影響者（中） | S-2 AIエージェント群 | 承認待ちの記録 `[?]` を残すかどうかが運用次第でばらつく（intent-statement の R-1）。表示の正確さに直結する |
| 影響者（弱・将来） | S-4 将来の OSS 利用者 | 現時点では要件に直接は入れない。設計の判断で迷ったときの参考にとどめる |

### 影響度と関心度の整理

| | 関心度：高 | 関心度：低 |
|---|---|---|
| **影響度：高** | S-1 開発者本人（主体的に関与） | S-3 フレームワークの作り手（形式の変化を見張る） |
| **影響度：低** | S-4 将来の OSS 利用者（公開時に配慮） | S-2 AIエージェント群（データの出どころとして扱う） |

説明: 開発者本人は影響も関心も高く、すべての判断に関わります。フレームワークの作り手はこのプロジェクト自体への関心はないものの、データの形式を決めるため影響が大きい相手です。将来の OSS 利用者は関心は高いが、現時点での影響は小さい相手です。AIエージェント群は、データの出どころとして扱います。

## 3. コミュニケーションの要件

| 経路 | 内容 | 手段 | タイミング |
|------|------|------|-----------|
| ダッシュボード → S-1 | 承認待ちの件数 | ブラウザのタブのタイトル（全プロジェクトの合計件数） | 承認待ちの件数が変わったら数秒以内 |
| ダッシュボード → S-1 | 承認待ち・修正中・各 Intent の状況 | 開きっぱなしのブラウザ画面（リロード不要で自動反映） | ファイル変更の検知時 |
| S-1 → AIエージェント群 | 承認・差し戻し | Claude Code 上の承認ゲート（ダッシュボードからは行わない） | S-1 が承認待ちに気づいたとき |
| S-3 → S-1 | フレームワークの形式変更 | フレームワークの更新履歴・ドキュメント（ダッシュボードの外） | フレームワーク更新時。追従の方針は feasibility 以降で決める |
| ダッシュボード → S-1 | 読めない・壊れたファイルやプロジェクトの警告 | ダッシュボード上の警告表示（他のプロジェクトの表示は続ける） | 検知時 |
| S-1 → S-4（将来） | 使い方・設定方法 | ドキュメント（OSS公開時） | 公開を決めたとき |

## 4. このプロジェクトで「やり取りしない」もの

- ダッシュボードからの承認操作（承認は必ず Claude Code 上で行う）
- Slack などの外部への通知
- 監視対象プロジェクトの `aidlc/`・`.claude/` への書き込み（エージェントやフレームワークへの働きかけは一切しない）
