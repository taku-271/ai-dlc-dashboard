# Intent Statement: AI-DLC 並列 Intent ダッシュボード（v1）

> 入力元: ユーザーの依頼文（audit に記録）と `intent-capture-questions.md` の回答

## 課題（Problem Statement）

AI-DLC で複数の Intent を並列に進めると、「どの Intent が自分の判断を待っているか」を探す作業そのものが負担になっている。各 Intent の状態は個別のファイルに分かれており、全体を一度に見渡す手段がない。

## 対象利用者（Target Customer）

- 当面の利用者: 依頼者本人（AI-DLC を Claude Code 上で使い、普段 4〜6 件の Intent を並列で進める開発者）
- 将来の利用者: チームメンバーと管理者（チーム展開を前提に設計する）

## 成功指標（Success Metrics）

| 指標 | 合格基準 |
|------|----------|
| 全体の把握 | 一画面で、今動いているすべての Intent とその状態がわかる |
| 実データでの正確さ | このリポジトリで並列に動いている実際の Intent が、漏れなく正しく表示される |
| 反映の速さ | ファイルが更新されてから数秒以内に画面に反映される |
| 読み取り専用 | ダッシュボードの動作によって `aidlc/` と `.claude/` に書き込みが一切発生しない |
| 推測しない | 取得できなかった情報は推測値ではなく「取得不可」と表示される |

※ 依頼者の回答では「一画面ですべての Intent がわかること」が最重要。「人待ち Intent の影響順の並び」などその他の受け入れ条件は、要件定義の段階で確定させる。

## きっかけ（Initiative Trigger）

並列で進める Intent の数が増え（普段 4〜6 件）、判断待ちを見つけるための確認作業が目立つようになったこと。

## スコープの方針（Initial Scope Signal）

- `poc` スコープで、短い単位で進める
- 本 Intent の対象は v1（読み取り専用ダッシュボード）のみ
- v2（判断の下書き生成）は、v1 の確認後に別の Intent として起こす
- v3（ダッシュボードからの直接承認、チーム向けビュー）は対象外
- 読む対象は当面このリポジトリの `aidlc/` だけ

## 制約

- ダッシュボードは `aidlc/` と `.claude/` を読み取り専用で扱う
- 承認・差し戻しは Claude Code の会話内で行い、ダッシュボードからは行わない
- 外部サービスへの送信をせず、ローカルで完結する
- macOS / Linux / WSL で動く

## 仮定（Assumptions）

- 仮定1: このリポジトリで今後 4〜6 件の Intent を並列で進める。現時点では本 Intent 1 件しかないため、実データでの確認には Intent を追加で用意する必要がある
- 仮定2: 「今動いている Intent」とは、完了していない Intent を指す。完了済みの Intent の扱い（表示する／件数だけにする）は要件定義で決める
