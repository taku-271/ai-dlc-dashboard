# Requirements Analysis 質問票

`aidlc/` の実ファイル調査（`requirements.md` の「データ取得可否の調査結果」に記載）を踏まえ、要件を確定するのに必要な4点だけを確認します。

## 質問1: v1 に含める画面の範囲はどうしますか？

調査の結果、一覧画面に必要な情報（現在ステージ、承認待ち、待ち時間）はファイルから機械的に取れます。一方で、承認待ち詳細の3区分（AI の仮定、上流から辿れない追加、抜け候補）に必要な「仮定の一覧」と「要件 ID のトレーサビリティ」は、AI-DLC 側に決まった書式がないため取得できません。

A. v1 は一覧画面と簡易詳細（ステージ進捗、直近の audit、成果物へのリンク、git diff）に絞る。3区分レビューは v2 以降で、書式の取り決めとセットで扱う（推奨）
B. v1 に3区分レビューも含め、取れない区分は「取得不可」と表示する
C. v1 で書式の取り決め（仮定や ID の書き方）も決め、3区分レビューまで作る
X. Other (please specify)

[Answer]: X（最小で、一覧画面だけで良い）

## 質問2: 「ブロック（人が対応すべき停止）」に何を含めますか？（複数選択可 / select all that apply）

AI-DLC には「ブロック」という状態がありません。代わりに使えるシグナルは次のとおりです。

A. 失敗で止まって人の判断を待っている（`BOLT_FAILED` / `SWARM_UNIT_FAILED` / `ERROR_LOGGED` の後に再開していない）
B. 質問ファイルに未回答の回答欄が残っている（AI が人の回答を待っている）
C. ステージの途中でセッションが終わったまま放置されている（`SESSION_ENDED` の後に再開がない）
D. センサーが失敗した（`SENSOR_FAILED`。AI-DLC 上は助言扱いで、作業は止まらない）
X. Other (please specify)

[Answer]: A, B, C

## 質問3: 技術スタックはどうしますか？

A. Bun + TypeScript。サーバーは Bun 標準機能、画面は素の HTML/TS、更新通知は SSE、テストは `bun test`。追加の依存がほぼなく、AI-DLC と同じく bun だけで動く（推奨）
B. Node.js + Vite + React。部品化しやすく、v2 の対話的な画面も作りやすいが、依存とビルドが増える
C. Python（FastAPI など）+ 素の HTML
X. Other (please specify)

[Answer]: A

B. 確認の前に、あなたが実際の Intent を追加で起こす
C. A と B の両方
